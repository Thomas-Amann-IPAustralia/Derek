# Postmortem: Octavius v1

**Status:** Closed. Superseded by Derek.
**Date:** 2026-09-21
**Purpose:** This document exists so that no decision, defect or omission from Octavius
is silently repeated in Derek. Every claim below is reproducible from the Octavius
repository at commit `d9cd29f`.

Read this before proposing any change to Derek's extraction or detection layers.
Most "good ideas" for this problem have already been tried here and have a recorded
outcome.

---

## 1. The headline result

Octavius shipped a rulebook of **3,114 extracted rules**, of which **801 were marked
`test_result: "pass"`** and loaded into the running linter.

Those 801 rules were fired against the Australian Government Style Manual's **own
prose** — 186 pages, 206,511 words of professionally edited APS content written by the
people who author the rules, with the manual's deliberate counter-examples
("Not this", "Incorrect" blocks) removed first. This is the single most compliant
corpus that exists.

| Measure | Result |
|---|---|
| Findings raised | **297,038** |
| Findings per 1,000 words | **1,438.4** |
| Rules that fired at least once | 710 / 801 (89%) |
| Rules exceeding a zero density budget | 710 |
| Rules that crashed on real text | 0 |
| Rules that timed out (catastrophic backtracking) | 0 |

The linter reports roughly **1.4 violations per word** on text that is by definition
correct. The rulebook was not merely noisy; it carried no signal at all.

The noisiest individual rules:

| Findings | Rule | Statement |
|---|---|---|
| 16,602 | `how-people-read-025` | "Use line breaks to package information effectively." |
| 16,565 | `how-people-read-028` | "Avoid line breaks that break ideas in the wrong place." |
| 14,681 | `…types-words--nouns-020` | "Avoid noun trains by rewriting sentences that contain strings of three or more nouns." |
| 12,924 | `how-people-read-024` | "Use paragraphs to help readers find and absorb ideas." |

Reproduce, from a Derek checkout:

```bash
python -m derek.eval.dogfood --octavius reference/octavius-v1/rules_working_draft.v1.jsonl
```

The same gate now runs against Derek's own ledger in CI
([ADR-011](02-decisions.md#adr-011-the-dogfood-gate)), so this measurement is a
permanent standing check rather than a one-off autopsy.

**The critical observation is not that the rules were bad. It is that every one of
those 801 rules passed its own test suite.** Phase 4 reported "801 pass". The tests
were generated by the same model, in the same call, as the rules they tested. The
test suite measured self-consistency, not correctness, and so it certified a rulebook
with a false-positive rate of effectively 100%.

> **Derek invariant D-1:** No rule may be validated only against examples authored
> alongside it. Every rule is additionally gated against an independent corpus it
> did not see. See [ADR-011](02-decisions.md#adr-011-the-dogfood-gate).

## 2. Failure taxonomy

Each failure mode below is a distinct root cause with a distinct fix. They compound:
a single rule frequently exhibits three or four at once.

### F1 — Polarity inversion (the fatal one)

The Style Manual states rules as **desired states**: "Use plurals when speaking about
collectives." A detector must fire on the **violation**, which is the negation of the
desired state. Octavius had no field, no convention and no test that distinguished the
two, so the code generator routinely produced a detector for the *compliant* pattern.

| Rule | Statement | `trigger_code` | `test_fire[0]` (asserted to be a violation) |
|---|---|---|---|
| `aboriginal-and-torres-strait-islander-peoples-004` | "Use plurals when speaking about collectives." | `\b(peoples\|nations\|cultures\|languages)\b` | `Aboriginal and Torres Strait Islander peoples` |
| `how-cite-style-manual-007` | "Introduce the shortened form Style Manual in parentheses at first mention." | `\bStyle Manual\b\s*\([^\)]*\bStyle Manual\b[^\)]*\)` | `The Australian Government Style Manual (Style Manual) sets the standard.` |
| `content-types--social-media-029` | "Address other users with an @ sign before their username." | `\B@\w+\b` | `Thanks for the update @JaneDoe` |
| `how-cite-style-manual-011` | "Use quotation marks for the title of a Style Manual webpage." | `["“][^"”\n]{3,}["”]` | `"How to cite the Style Manual"` |

In every row, the "violating" example is **perfectly compliant text**, and the rule
fires on correct usage while staying silent on the error. The test suite passed
because `test_fire` matched and `test_no_fire` did not — the assertions were
internally consistent and semantically backwards.

**Scale:** 500 of the 801 passing rules (62%) are phrased as positive instructions
(`Use…`, `Write…`, `Include…`, `Place…`, `Always…`). Every one of them requires
detecting an *absence*, which is the hard direction. None of them recorded which
direction their detector actually implemented.

> **Derek invariant D-2:** Every rule carries an explicit `violation_condition`
> describing what makes text **wrong**, and separate `compliant_examples` (must never
> fire) and `violating_examples` (must always fire). The field names make the
> direction unmistakable, and the schema rejects a rule that has only one kind.
> See [ADR-004](02-decisions.md#adr-004-polarity-is-a-first-class-schema-field).

### F2 — Detecting an absence with a pattern matcher

"Use numerals for 2 and above" cannot be expressed as a regex over arbitrary text,
because the rule is about what *should have been written instead*. Octavius forced
every rule into `regex` / `lookup` / `structural`, so positive instructions were
implemented as "match the topic and complain", which fires on every mention.

This is why `numbers-choosing-numerals-or-words-002` ("Use numerals for 2 and above")
raised 8,052 findings: it matched every spelled-out number in the corpus, including
the ones the Style Manual itself spells out correctly under its own exceptions.

> **Derek invariant D-3:** Detection method is chosen *after* determining whether the
> rule is a **presence** rule (something wrong is in the text) or an **absence** rule
> (something required is missing). Absence rules need a defined scope — the span
> within which the requirement must be satisfied — or they are not detectable.
> See [ADR-006](02-decisions.md#adr-006-presence-vs-absence-and-the-scope-requirement).

### F3 — Extraction from non-normative pages

108 of the 801 passing rules were extracted from pages that contain no content rules
at all:

| Source | Passing rules |
|---|---|
| `about-style-manual/changelog.md` | 22 |
| `style-manual-resources/**` (handbook, blog, quick guides) | 76 |
| `about-style-manual/how-cite-style-manual.md` | 6 |
| `about-style-manual/how-use-style-manual.md` | 4 |

The changelog describes *amendments to the manual*. The extractor read
"WWII replaces WW2" as a content rule and generated a detector for it. `how-cite-style-manual`
is about citing the Style Manual document — it applies to bibliographies that reference
the manual, not to APS writing generally.

> **Derek invariant D-4:** Page eligibility is decided **before** extraction, by an
> explicit, reviewable allowlist of corpus paths, not inferred per rule.
> See [ADR-005](02-decisions.md#adr-005-corpus-eligibility-is-declared-not-inferred).

### F4 — Harvesting the manual's prose instead of the pattern it describes

`how-people-read-020` — "Use short sentences to help people build reading rhythm" —
compiled to:

```
(?m)^\s*[-•]\s*.*\bshort sentences\b|\bshort sentences\b.*\bline breaks\b|…
```

It matches the literal phrase "short sentences". The generator, unable to implement
the rule, produced a detector for the *sentence of the Style Manual that states the
rule*. It passed its tests because the test strings were also drawn from that prose
(`test_fire[0]` is `- short sentences`).

This class of rule fires only on documents that discuss style — which includes every
page of the Style Manual, hence the 16,000-finding rules at the top of the table.

> **Derek invariant D-5:** A rule's examples may never be drawn from the sentence that
> states the rule. Derek harvests examples from the manual's own **Write this / Not
> this** blocks, which are separate, editorially authored, and correctly polarised.
> See [§4](#4-what-is-worth-keeping).

### F5 — Rules about artifacts, not text

The rulebook contained rules that no text linter can evaluate:

- `content-types--video-and-audio--requirements-and-standards-video-and-audio-010` —
  "Make video text contrast at least 4.5:1" → compiled to a regex matching any number
  below 4.5 anywhere in the text.
- `content-types--social-media-026` — "Use no more than two hashtags" → fires on any
  paragraph containing three `#` tokens, including markdown headings.
- `page-optimisation-018` — "Keep titles to 70 characters or fewer" → 7,583 findings,
  because it had no concept of *which* span is a title.

These are rules about images, video files, social posts and page metadata. Applied to
a policy document they are pure noise.

> **Derek invariant D-6:** Every rule declares an `applies_to` (content types) and a
> `unit` (the span it evaluates: character, token, sentence, block, document,
> or `artifact`). Rules with `unit: artifact` are recorded, marked
> `detectable: false`, and never loaded into the text runtime.
> See [ADR-007](02-decisions.md#adr-007-scope-and-unit-are-mandatory).

### F6 — Over-extraction and duplication

181 corpus pages yielded 3,114 rules — a mean of **17.2 rules per page**, with
`content-types/easy-read.md` alone producing 41. The manual's own structure exposes
**1,795 `###` headings across the whole corpus**, and those headings *are* the
normative statements. The LLM was generating roughly twice as many "rules" as the
document contains, by splitting explanatory prose into pseudo-rules.

53 rule summaries were verbatim duplicates of another rule (60 redundant rows), each
with an independently generated detector, so the same finding could be raised several
times under different rule IDs.

> **Derek invariant D-7:** The rule inventory is derived **deterministically from
> document structure**, not proposed by a model. A model may classify and formalise a
> candidate; it may not decide that a candidate exists.
> See [ADR-002](02-decisions.md#adr-002-deterministic-candidate-identity).

### F7 — Change detection that could not detect change

`src/scrape.py` decided what to re-fetch with:

```python
urls_to_scrape = [
    entry for entry in urls
    if entry["loc"] not in sitemap_state
    or sitemap_state[entry["loc"]] != entry.get("lastmod")
]
```

Three defects, each of which independently breaks the requirement that Derek identify
new, altered and removed rules:

1. **Silent edits are invisible.** If a page is edited without its sitemap `lastmod`
   advancing — a routine occurrence in Drupal when content is updated via certain
   workflows — the page is never re-fetched. The content manifest computes SHA-256 for
   every page, but only over files already on disk, so it can never notice.
2. **Removals are never processed.** A URL that disappears from the sitemap is not
   deleted from `content/`, is not removed from `sitemap_state.json`, and raises no
   signal. The retired page's rules stay live forever.
3. **No diff is produced.** The scrape commits changed files; nothing computes or
   records *what changed within* a page, so there is no input to a rule-level
   reconciliation step.

Additionally the workflow ran on `cron: '0 0 1 * *'` — **monthly**. Worst-case staleness
was 31 days against a 3-day requirement.

A fourth, subtler defect: GitHub disables scheduled workflows after 60 days of
repository inactivity. A monthly job on a quiet repository is one missed month away
from stopping altogether, silently.

> **Derek invariant D-8:** The snapshot layer emits an explicit `added / altered /
> removed` changeset per run, computed from content hashes rather than site-supplied
> metadata, with a periodic full re-hash sweep that does not trust `lastmod`.
> See [ADR-001](02-decisions.md#adr-001-snapshot-integrity-over-site-metadata).

### F8 — Non-deterministic extraction

Phases 2, 3, 3.5 and 5 each made batched LLM calls whose outputs were written straight
into `rules_working_draft.jsonl`. Nothing was content-addressed or cached. Re-running
the pipeline over an unchanged corpus produced a different rulebook: different rule
IDs, different counts, different code. There was no way to tell a genuine Style Manual
change from model variance.

The git history shows the symptom plainly — fifteen consecutive commits titled
`Phase 4: test results — 801 pass, 61 fail, 2064 skip, 188 frozen`, re-running a
pipeline whose output nobody could diff.

> **Derek invariant D-9:** Model outputs are content-addressed by
> `(candidate_uid, prompt_version, model_id)` and committed. A cached decision is never
> recomputed. Re-running over an unchanged corpus is a no-op by construction.
> See [ADR-003](02-decisions.md#adr-003-model-calls-are-a-cache-not-a-step).

### F9 — Premature delegation

The decisive process failure, and the one the rest follow from. Rule interpretation —
the judgement about what a rule means, whether it is automatable, and what would count
as a violation — was handed to a batch LLM job before a single rule had been worked
through by hand. By the time a human looked at the output there were 3,114 rows, which
is past the point where anyone can review them.

The correction is not "use a better model". It is to make **review a gate rather than
an afterthought**, and to keep the reviewable unit small enough to actually review.

> **Derek invariant D-10:** A rule is `proposed` until a human accepts or amends it.
> Only `accepted` rules load into the runtime. The ledger records who decided, when,
> and why, and the review UI is built before the rule volume grows.
> See [ADR-008](02-decisions.md#adr-008-human-acceptance-is-a-gate-not-a-review-queue).

## 3. Defects that were not rule-quality problems

These are real and would have bitten again.

| # | Defect | Where | Consequence |
|---|---|---|---|
| 1 | Heading levels are flattened inconsistently by `trafilatura` | `src/scrape.py:html_to_markdown` | The corpus had 1,795 `###` but only 53 `##` and 2 `#`, with section headings demoted to plain paragraphs. Since structure-driven extraction reads rules off the heading tree, this silently changed which rules exist. **Fixed:** `derek/corpus/to_markdown.py` takes heading levels from the source DOM ([ADR-020](02-decisions.md#adr-020-heading-levels-come-from-the-dom)); `trafilatura` is removed from the pipeline. |
| 2 | `__builtins__` exposed to rule code | `logic/rulebook/adapters.py:_RULE_EXEC_GLOBALS` | `exec()` of model-generated code with full builtins. Acceptable when the code is reviewed; unacceptable when it is generated in batches of thousands and merged unread. |
| 3 | Test-generation and rule-generation share a model call | `src/generate_code.py` | The root cause of the "801 pass" illusion (§1). |
| 4 | `test_result` doubles as lifecycle state | schema | `pass`/`fail`/`skip`/`frozen` conflates "the tests passed" with "we decided not to ship this". Derek separates `validation` from `review_status`. |
| 5 | No calibration of confidence | runtime | Findings had a binary severity derived from `discretionary_flag`. A confidence slider over uncalibrated outputs is meaningless. |
| 6 | Findings budget masked the problem | `logic/indexed_dispatcher.py` | A cap of 5 findings per rule and document-level gating hid the 1,441/1,000 signal from anyone using the UI. Suppression made a broken rulebook look merely noisy. |

Defect 6 deserves emphasis: **the product-level mitigations were load-bearing.** Budgets,
dedup and doc-level gating were introduced to make the output tolerable, which removed
the pressure to discover that the rulebook was non-functional. Derek measures rule
quality *before* any suppression, and the dogfood gate runs on raw, ungated output.

## 4. What is worth keeping

| Asset | Kept as | Why |
|---|---|---|
| Offline Style Manual snapshot (186 pages) | `corpus/pages/` | The foundation. Accurate, complete, and expensive to rebuild. |
| Sitemap state and content manifest | `corpus/*.legacy.json` | Seeds the new lock file; preserves known `lastmod` history. |
| Scraper transport (Selenium fallback, stealth, robots.txt handling, XSLT sitemap parsing) | `derek/corpus/fetch.py` | Hard-won. The Style Manual's WAF drops plain `requests` traffic and its sitemap is XSLT-rendered HTML; both were solved correctly. The *converter* it fed (`trafilatura`) is not kept — see Defect 1. |
| Curated markdown rule library (90 pages) | `reference/style-manual-curated/` | Cleaner structure than the scrape on some pages; useful for cross-checking extraction fidelity. |
| Inverted-index dispatcher design | `reference/octavius-v1/OCTAVIUS_REFACTOR_LOG.md` | The feature-gating idea is sound and the decision log is detailed. The implementation is not reused, but the reasoning about zone/offset invariants and batching carries directly into Derek's document model. |
| v1 rulebook (3,114 rows) | `reference/octavius-v1/rules_working_draft.v1.jsonl` | **Non-authoritative.** Two legitimate uses: (a) a *recall checklist* — did Derek's deterministic extractor find the rules a model found? (b) a permanent negative test set for the dogfood gate. |
| LLM prompts | `reference/octavius-v1/prompts/` | Kept to learn from. Note that `prompts/regex.md` never mentions polarity — the root cause of F1 is visible in the prompt itself. |

### The asset Octavius never noticed

The Style Manual authors **compliant/violating example pairs directly into the corpus**:

```markdown
#### Write this
There were 16.5 million people enrolled to vote in Australian elections on 18 April 2019.

#### Not this
On 18 April 2019, 16.5 million people were enrolled to vote in Australian elections.
```

Across the corpus there are **122 `Write this` blocks, 169 `Not this` blocks and 1,055
`Example` blocks** — hand-authored, correctly polarised, attributable to a specific
rule by document position, and written by the people who own the rules.

Octavius generated its own test strings with an LLM and ignored this entirely. Derek
harvests them as the seed evaluation set (`derek/extract/examples.py`). They are the
starting point for the handwritten fine-tuning set, and they arrive with provenance
already attached.
